# MISSION-18: feat: add action cards for intent discovery and task confirmation in deep dive flow

## Objective

在 deep dive 流程中增加 **action card 交互层**，让用户在两个关键节点做出选择：
1. **意图发现阶段** — agent 分析用户意图后，展示可选动作按钮（如 "Search prices", "Get directions", "Learn more"），用户点击后推动交互进入下一步
2. **任务确认阶段** — 正式执行长线任务前，展示 Start / Cancel / Chat about it 选项，用户确认后才启动 gateway dispatch

用户点击 action card 后需触发 agent 响应，形成完整的交互闭环。

## Sub-tasks

- [x] **Agent 意图发现 action card**：在 `agent_common.py` 的 `handle_f2b_send_message` 中，`[USER_DISPATCH]` 到达后，agent 先分析意图，调用 `rpc_b2f_show_action_card` 展示选项，而非直接 dispatch
- [x] **Agent 任务确认 action card**：用户选择了意图后，agent 发送确认卡片 (Start/Cancel/Chat about it)，等待用户确认
- [x] **Agent 响应处理**：在收到用户 action card 选择（通过 `rpcF2BSendMessage`）后，根据选项决定：Start → 调用 `rpc_b2g_dispatch_message`；Cancel → 语音反馈+回到待命；Chat → 继续对话收集更多信息
- [x] **前端 ActionBar 适配**：确保 `ActionBar` 组件在 deep dive / LiveSessionView 状态下正确展示，点击后自动 dismiss，不影响流式 HTML 渲染
- [x] **System prompt 更新**：更新 `base.md` 中的 tool routing guide，指导 agent 在 dispatch 前使用 action card 交互

## Acceptance Criteria

- [ ] 意图发现阶段：agent 分析完意图后，通过 `rpc_b2f_show_action_card` 发送 2-4 个上下文相关的选项按钮
- [ ] 任务确认阶段：在调用 `rpc_b2g_dispatch_message` 前，展示 Start / Cancel / Chat about it 确认卡片
- [ ] 用户点击 action card 选项后，agent 正确接收并处理（Start → dispatch, Cancel → dismiss, Chat → 继续对话）
- [ ] Action card 在 LiveSessionView 的 deep dive 页面中正确渲染，不遮挡流式内容
- [ ] 整个流程端到端可用：拍照 → 意图发现卡片 → 用户选择 → 确认卡片 → Start → 流式页面

## Constraints

- 不要新增 DataChannel topic 或 RPC method，复用现有的 `rpc_b2f_show_action_card` + `rpcF2BSendMessage` 管道
- Action card 最多 4 个选项（现有限制）
- 意图发现阶段的选项需要根据场景动态生成（由 agent/LLM 决定），不能硬编码
- Cancel 后不能留下残留的 gateway task
- 保持现有的"直接 dispatch"作为 fallback（如 agent 判断意图明确无需确认时可跳过）

## AI Notes

- Completed: 2026-03-03 (v1 — RPC-based, rejected)
- Redesigned: 2026-03-03 (v2 — gateway HTML cards)
- Key decisions:
  - **Architecture change**: Action cards are now generated by the **gateway as streamed HTML** (displayed as normal CanvasCards), NOT via `rpc_b2f_show_action_card` RPC
  - State machine (`_action_card_phase`) with 3 states: `None` → `intent_discovery` → `task_confirmation`
  - Intent discovery: `rpc_b2g_dispatch_message` with `reply_hint` instructing gateway to generate action card HTML with `data-action="vi_select"` buttons
  - Confirmation card: gateway generates Start/Cancel/Chat HTML card (same mechanism)
  - Final dispatch: gateway receives confirmed task and streams result HTML
  - Frontend bridge script forwards `vi_select` clicks as `[ACTION_CARD_SELECT] {"selected": "...", "options": [...]}` via `sendMessage` RPC
  - Fallback to direct dispatch if gateway fails
  - "Chat about it" resets phase but preserves `_pending_dispatch_text` so user can proceed later
- Files modified:
  - `realtime/src/agent_common.py` — rewrote action card flow to use gateway dispatch with `reply_hint`
  - `realtime/src/base.md` — updated system prompt for gateway-based action card flow
  - `frontend/src/components/LiveSessionView.jsx` — added `vi_select` case in `handleAction` to forward selections to LiveKit
