# Plan: Add Alembic Database Migrations
## Contract: .claude/drive/alembic-migrations/contract.md

## Approach Overview
Add Alembic with the async migration runner to the api-server. The key change: Base.metadata gets a naming convention (for stable autogeneration), Alembic env.py uses the existing async engine, and the initial migration captures the full current schema. Production startup switches from create_all() to relying on pre-run `alembic upgrade head`.

## Architecture / Design

```
api-server/
├── alembic.ini                    ← Alembic config (sqlalchemy.url from env)
├── alembic/
│   ├── env.py                     ← Async migration runner, imports Base + engine
│   ├── script.py.mako             ← Migration template
│   └── versions/
│       └── 001_initial_schema.py  ← Captures users + sessions + agent_memories
├── app/
│   ├── models.py                  ← Add naming_convention to Base.metadata
│   └── main.py                    ← Remove create_all(), log migration reminder
└── requirements.txt               ← Add alembic>=1.14.0
```

## Key Design Decisions
- **Naming convention on metadata** — uses SQLAlchemy's standard convention: `ix_%(column_0_label)s`, `uq_%(table_name)s_%(column_0_name)s`, etc. This makes autogenerated constraint names predictable and diff-stable.
- **env.py async runner** — uses `run_async_migrations()` with `connectable = create_async_engine()`. Reads DATABASE_URL from environment (same source as config.py).
- **alembic.ini sqlalchemy.url left empty** — env.py overrides it from the environment variable, preventing hardcoded credentials in config files.
- **init_db() simplified** — instead of create_all(), it becomes a no-op or logs a reminder to run migrations. Tests override with create_all() in their own fixture.

## Implementation Sequence
1. Add naming convention to Base.metadata in models.py
2. Add alembic to requirements.txt
3. Initialize Alembic (alembic init -t async alembic) inside api-server/
4. Configure alembic.ini (set script_location, clear sqlalchemy.url)
5. Configure env.py (import Base.metadata, use async engine from DATABASE_URL)
6. Generate initial migration (alembic revision --autogenerate -m "initial schema")
7. Review and clean up the generated migration
8. Modify init_db() to not call create_all()
9. Update main.py lifespan to handle the change
10. Verify: fresh DB + alembic upgrade head works
11. Verify: autogenerate shows no pending changes

## Risk Mitigation
- Named constraint conflict: The existing `uq_agent_memories_user_filename` constraint was manually named. The new naming convention will generate a different name for it. We'll keep the explicit name in the model to avoid a rename migration.
- Test isolation: Tests will use their own create_all() in conftest.py, independent of Alembic.

## What This Plan Does NOT Cover
- Migration to Mapped[] annotations (separate effort, no functional change)
- Production deployment runbook (depends on deployment tooling decisions)
- CI/CD integration for migration checks
