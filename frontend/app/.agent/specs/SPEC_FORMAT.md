# PRD 需求文档格式规范

本文档定义 PRD（产品需求文档）的标准格式，便于 AI 解析和理解需求。

## 文件位置

所有功能需求文档存放在：`.agent/specs/features/[功能名].md`

## 标准模板

```markdown
# [功能名称]

## 概述

简要描述功能目标和背景（1-2 句话）

## 用户故事

作为 [用户角色]，我希望 [功能描述]，以便 [达成目标]

## 功能需求

### 核心功能
- [ ] 功能点 1
- [ ] 功能点 2
- [ ] 功能点 3

### 可选功能
- [ ] 可选功能点 1

## UI/交互要求

### 页面结构
描述页面的主要区域和布局

### 交互说明
| 触发元素 | 触发方式 | 行为 |
|---------|---------|------|
| 按钮A | 点击 | 跳转到页面B |
| 列表项 | 长按 | 显示操作菜单 |

### 动画要求
- 页面进入：从右滑入
- 加载状态：使用 Shimmer 效果

## 数据要求

### 输入数据
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| name | String | 是 | 用户名称 |

### 输出数据
| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 唯一标识 |

## 关联资源

- JSX 原型：[组件路径，如 .agent/design/reference-design/src/components/XxxView.jsx]
- API 文档：[路径或链接]
- 相关页面：[页面名称]

## 验收标准

1. [ ] 验收条件 1
2. [ ] 验收条件 2
3. [ ] 验收条件 3

## 备注

其他补充说明
```

## 示例

见 `.agent/specs/features/user-profile.md`

## AI 解析说明

AI 在解析 PRD 时会重点关注：

1. **用户故事** - 理解功能的核心价值
2. **功能需求** - 确定需要实现的功能点
3. **UI/交互要求** - 确定页面结构和交互逻辑
4. **数据要求** - 确定需要的 Model 结构
5. **验收标准** - 作为功能完成的检查清单
